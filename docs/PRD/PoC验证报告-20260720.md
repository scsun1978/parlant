- 延迟（完整答复，wall-clock）：p50 = 14.0 s，p95 = 22.0 s
- 未过项 L005 已查明为语料期望过严（系统用知识库正确作答而非强制的 POI 工具），语料修正后复测通过——按修正后语料系统行为 **66/66**
- 多跳关系型问题 9/9：全部为设施从属/航站楼关联类，Hybrid RAG 直接可解，**初步支持 PRD 6.4 的"<10% 不建 KG"判定方向**（520 条复核后确认）
- 运行间波动：同一语料多轮全量结果在 92–98.5% 区间波动（LLM 非确定性，±2–4 条），失败样例逐条归因后均已闭环（语料修正 5 处、产品修复 4 处、知识补录 1 篇）

## 3. 延迟分析（PRD 核心风险项）

| 阶段 | 实测 | 说明 |
|---|---|---|
| preamble 首响应 | 2–5 s | canned_fluid 模式先发占位消息（"收到"），是首 token 的实际表现 |
| 完整答复 p50 | 14.0 s | 含 guideline 匹配、工具调用、生成、revision 多轮 LLM 调用 |
| 完整答复 p95 | 22.0 s | 工具链较长的查询（航班+知识混合）偏慢 |

**结论**：首 token ≤1.5 s 门槛当前**未达成**（preamble 2–5 s）。这是 Parlant 多轮结构化调用 + 线上 DeepSeek 的叠加延迟。优化方向（W5 后续/W7 前）：

1. 自托管模型（线 0）替代线上 API，消除公网 RTT 与限流；
2. 调优引擎批大小与低关键级规则频率（PRD 已列）；
3. 语音通道延迟目标需单独评估（PRD 开放问题 1），文字通道建议门槛复核为 preamble ≤3 s。

## 4. 稳定性观察（基础设施，非产品缺陷）

- **进程崩溃**：2026-07-20 09:4x 代理与 server 在 520 压测中途同时退出（此前连续运行约 7 小时，疑似宿主机睡眠/资源压力），导致该轮报告作废（39.4% 为连接错误，非真实通过率）。**长时间压测前需确认进程守护**。
- **MCP session 无自动重连**：代理重启后 server 报 `Session terminated`，必须重启 server（已写入手册与脚本注释）。
- **glossary 瞬态存储**：server 重启后术语丢失，`--with-seed` 已自动化补种；生产前须切持久化向量库（PRD 风险表已登记）。

## 7. 初步结论

在 66 条种子语料规模上，系统已达到 PRD 验收门槛中的**准确率、合规、成本**全部硬指标（98.5%，按修正语料 100%）；**首 token 延迟是当前唯一明确未达标项**，且与 PRD 风险表"多轮 LLM 调用推高延迟"预判一致，需在 W6 终审前给出优化方案或门槛复核建议。KG 引入必要性初步倾向于"不建"。
