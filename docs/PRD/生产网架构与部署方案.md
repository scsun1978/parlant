## 1. 设计原则

1. **数据不出域**：生产环境 LLM 全部自托管（线 0），无任何公网 LLM 调用；DeepSeek 线上 API 仅限 PoC 使用，生产禁用。
2. **高合规物理可控**：话术模板 + composited_canned 组合模式沿用 PoC 验证结论；strict_canned 暂不启用（PoC 实验结论：模板覆盖不足）。
3. **可用性 99.9%**：无单点——应用层 ≥2 副本，数据层全部集群化，LLM 双活。
4. **持久化替代瞬态**：PoC 暴露的瞬态向量库、JSON 文档库全部替换为生产级存储（MongoDB / Qdrant / ES）。
5. **容量可估算**：一切 sizing 假设显式标注（§4），随灰度实测数据滚动修正。

### 2.2 关键架构决策（相对 PoC 的变化）

| # | 决策 | 理由（PoC 证据） |
|---|---|---|
| 1 | **LLM 全自托管双活**，禁用线上 API | PRD 数据不出域硬要求；同时消除公网 RTT——PoC 首 token 未达标（2–5 s）的主因之一 |
| 2 | **Parlant 3 副本 + 前置会话亲和** | PoC 确认单进程架构；按 PRD 风险缓解，网关上按 conversationId 一致性哈希分发 |
| 3 | **持久化向量库（Qdrant）替换瞬态库** | PoC 实测 glossary 重启丢失；同时承载知识/话术向量 |
| 4 | **RAG 拆为独立无状态服务**（BM25 查 ES + 向量查 Qdrant + RRF + Rerank） | PRD 既定决策；PoC 内嵌实现已验证检索质量，拆分后可独立扩缩容与发版 |
| 5 | **MongoDB 副本集替代 JSON 文档库** | PoC 默认 JSON 文件库非生产级；Parlant 原生支持 Mongo |
| 6 | **MCP 工具网关化 ×2 + 熔断降级** | PoC 出现上游超时与"Session terminated"连锁故障；网关注入健康检查/重试/熔断，工具失败时降级口径 + 转人工（FR-406） |
| 7 | **进程守护与自愈**（K8s liveness/readiness + systemd 兜底） | PoC 两次长跑静默死亡，生产必须自动拉起并告警 |
| 8 | **OTEL 全链路 trace 入监控栈** | FR-701/702 审计回放与幻觉/延迟/成本看板（FR-703）的数据基础 |

## 3. 服务器资源清单

### 3.1 生产环境

| 分区 | 角色 | 规格 | 数量 | 用途与 sizing 依据 |
|---|---|---|---|---|
| 接入区 | API 网关 / WAF | 8C16G，万兆 | 2 | 鉴权、限流、审计日志、会话亲和路由（Nginx/APISIX） |
| 应用区 | Java 业务后端 | 16C32G | 2 | 渠道适配、会话映射、转人工工单、与机场会员/客服系统对接 |
| 应用区 | Parlant 服务 | 16C32G | 3 | 对话引擎；PoC RSS ~1.1 GB 起、加载嵌入模型后 ~3–4 GB，3 副本承载峰值并发并留一副本滚动发布 |
| 应用区 | 管理后台 BFF + 前端 | 8C16G | 2 | 运营后台（规则/话术/知识/审计），Nginx 静态托管 + BFF |
| 应用区 | MCP 工具网关 | 8C16G | 2 | 航班/订单/退改签/失物 MCP 封装、熔断降级；PoC 代理 RSS ~4.1 GB（含 torch），生产改纯转发无模型后可降至 ~1 GB |
| AI 算力区 | LLM 推理服务器 | 8×A800/H800 80G + 512G 内存 + 8T NVMe | 2 | vLLM/SGLang 双活；主力模型（DeepSeek-V 系 / GLM / Qwen3 候选之一）+ Embedding + Rerank 同机混部 |
| 应用区↔AI | RAG 检索服务 | 16C32G | 2 | 无状态检索编排（ES+向量+RRF+Rerank 调用）；Rerank 大模型走 GPU |
| 数据区 | MongoDB | 16C64G，1T SSD | 3 | 副本集：会话/事件/规则/话术/审批/trace |
| 数据区 | Elasticsearch | 16C64G，2T SSD | 3 | BM25 中文分词索引（888 篇基线，按 10 万篇/年扩容） |
| 数据区 | Qdrant | 16C64G，1T SSD | 2 | 知识/术语/话术向量（768 维基线，预留 1024 维切换空间） |
| 数据区 | MinIO/S3 | 8C32G，4T | 2 | 知识 release 快照、备份、审计归档 |
| 运维区 | 监控栈 | 16C32G，2T SSD | 2 | Prometheus/Grafana/Loki/Tempo(OTEL) |
| 运维区 | 堡垒机 + 发布机 | 8C16G | 2 | 运维审计、CI/CD 制品与执行 |

**合计：29 台**（含 2 台 GPU 服务器）。GPU 为唯一重资产；若终审选用 ≤32B 模型，单台可降至 4 卡。

### 3.2 非生产环境

| 环境 | 构成 | 数量 |
|---|---|---|
| 开发/测试 | 应用区合并 2 台 16C32G + 数据区合并 2 台 16C64G + GPU 1 台（4 卡即可） | 5 |
| 预发（灰度） | 生产最小集：各角色 1 台（GPU 复用生产推理集群单独命名空间） | 8 |

### 3.3 网络与存储

- 区内万兆互联；GPU 服务器建议 RDMA（vLLM 多卡张量并行）
- 数据区全 SSD；备份策略：Mongo/ES/Qdrant 每日快照至 MinIO，保留 30 天；审计归档保留 ≥3 年（民航留痕要求，FR-704）
- 生产网零出域默认策略；模型权重/依赖镜像经运维区白名单通道拉取后内网分发

## 4. 容量估算（假设显式可调）

### 4.1 流量模型

| 假设 | 取值 | 依据 |
|---|---|---|
| 年旅客量 | 7,600 万人次 | PVG 量级 |
| 智能客服日会话 | 4,000–8,000 | 按旅客 1–2% 触达、其中线上 70% 估算 |
| 峰值并发会话 | 60–120 | 日均 4 倍、小时集中系数 |
| 每会话轮次 | 4–6 轮 | PoC 观察 |
| **峰值引擎 QPS** | **3–6 轮次/秒** | 并发 × 轮次 ÷ 轮间隔 |

### 4.2 LLM 算力

PoC 实测单会话 ≈ ¥0.047（线上价）≈ **输入 ~15k tokens + 输出 ~1.5k tokens / 会话**（DeepSeek 价目反推，含引擎多轮调用）：

- 峰值吞吐需求：6 轮次/s × 2.5k 输入 ≈ **15k tokens/s 输入**、1.5k tokens/s 输出
- 70B 级模型 vLLM 8×A800 单台实测吞吐约 3–6k tokens/s 输出（视并发与量化）；**双活 2 台满足峰值并保留 N-1**，不足时先量化（AWQ/FP8）再加机
- Embedding/Rerank 与 LLM 同机混部（显存占用 <10%）

### 4.3 应用与数据层

- Parlant 单副本 PoC 实测支撑 4–6 并发评测无退化；生产按 **单副本 20 并发**保守取值，3 副本 60 并发 + 网关溢出排队
- MongoDB/ES/Qdrant 数据量首年 < 500 GB（trace 占大头，按 8,000 会话/日 × 50 KB 估算），现有规格余量 ≥5 倍

## 5. 高可用与故障预案

| 场景 | 预案 |
|---|---|
| Parlant 单副本挂掉 | K8s 自动拉起 + 网关摘除；会话亲和漂移后其他副本接管（会话状态在 Mongo，可续聊） |
| LLM 单机挂掉 | 双活切换；全挂 → 降级为**关键词 FAQ + 转人工**（PRD 非功能需求），降级状态全网告警 |
| MCP 工具超时/失败 | 网关熔断（30 s 半开）→ AI 给友好口径并可转人工（FR-406）；工具成功率 <98% 标红 |
| ES/Qdrant 单节点挂掉 | 集群内切换；RAG 服务对检索失败兜底为"未查到，转人工引导"（FR-204 红线：不得无源生成） |
| 机房级故障 | 本期单机房的同城冷备：数据每日异地快照，RTO 4 h / RPO 24 h（二期升级双活） |
| 进程静默死亡（PoC 观察） | liveness 探针（/healthz + 会话冒烟）+ 自动重启 + 告警；根因排查列入 W7 任务 |

## 6. 安全与合规

1. **零出域**：生产网默认拒绝公网出站；LLM/嵌入/检索全部内网闭环；PoC 使用的线上 DeepSeek API 与 PVG 测试凭据**必须轮换**（已在测试环境暴露于多份文档）。
2. **PII 脱敏**：会话与 trace 入库前脱敏（证件号/手机号/姓名）；日志不落凭据与签名（沿用 PoC 约定）。
3. **审计**：append-only 审计日志（FR-808）；单条回复证据链（规则×知识×模板版本）可导出归档；审计数据 ≥3 年。
4. **权限**：后台 RBAC 五角色 + 高合规变更双人复核（FR-801）；生产变更一律发布单 + 灰度 + 一键回滚（FR-806）。
5. **等保与民航评审**：接入区 WAF/IPS、运维全经堡垒机；评审材料（架构图/数据流/留痕方案）W7 前备齐。

## 7. 部署与发布

| 项 | 方案 |
|---|---|
| 形态 | 无状态服务全部 K8s（应用区/RAG/网关/BFF）；数据层与 GPU 裸机 + systemd |
| 环境通道 | 开发 → 测试 → 预发（灰度）→ 生产；预发与生产同拓扑最小集 |
| 发布 | 镜像 + Helm；规则/话术/知识经后台发布单灰度（FR-806），引擎版本与数据版本组合快照，一键回滚 |
| 知识更新 | bundle → 评审 → release 快照 → 索引构建（CI）→ ES/Qdrant 双写切换 → RAG 服务热加载（消除 PoC"重启代理+重启 server"操作） |
| 迁移 | Parlant schema 升级走 `parlant-prepare-migration` + `--migrate`，预发先行 |

## 8. 上线路径（对齐 PRD 第 8 章）

| 阶段 | 部署动作 |
|---|---|
| W7–8（P1 灰度） | 非生产环境就绪；生产数据区 + AI 算力区先行；5% 流量经预发通道灰度 |
| W9–10 | 生产应用区上线，30% 灰度；OTEL 看板与审计导出验收 |
| W11–14（P2 全量） | 全量切流；降级预案演练（LLM 全挂 → FAQ + 转人工）；民航合规评审收口 |

## 9. 开放问题

1. GPU 选型终审：A800/H800 vs 国产算力（910B），与模型选型（W6 bake-off）联动。
2. 会话亲和的分布式会话状态：Parlant 多副本共享 Mongo 是否完全无状态，需 W7 多副本实测验证（PRD 风险表已列）。
3. 机场既有客服系统（坐席工作台）的对接接口与工单协议，需客服系统团队确认（PRD 8.3 依赖表）。
4. 同城冷备是否满足民航可用性审计，或需直接上同城双活（成本 +40%）。
