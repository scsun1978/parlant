## 迭代 1 · 可靠性（约 2 周）

**目标**：消除"已读不回"，让系统在任何失败下都给旅客安全回复。

| 工作项 | 内容 | 验收标准 |
|---|---|---|
| 1-1 JSON 纠错重试 | `DeepSeekSchematicGenerator` 打补丁：schema 校验失败时用纠错 prompt 重试一次（含上次错误说明）；补丁回馈上游 | 多轮专项复跑，"已读不回"率 <2% |
| 1-2 渠道层兜底设计 | 兜底话术落在渠道/BFF 层（不落引擎，保持上游可升级）：超时/错误时发安全话术 + 可转人工；输出兜底话术清单与触发条件设计稿 | 设计评审通过，话术走审批流 |
| 1-3 静默死亡根因（时间盒 1 天） | 本机并发 6 复跑 520 压测 + watchdog（RSS/存活/退出码/系统日志采样）；嫌疑序：torch 并发 native 崩溃 > OneDrive 文件锁 > 内存尖峰 | 抓到签名则对症下药；抓不到则"自动拉起+告警"写入运维手册当已知风险 |
| 1-4 守护基线 | dev03 容器 restart 策略 + 健康检查 + 内存限额复核（server 6g 不可降）；告警接入 | 人工 kill 任一容器，30s 内自动恢复且会话可续 |

**依赖**：无。**出口门槛**：连续 100 轮零"已读不回"（灰度前置条件之一）。

## 迭代 2 · 延迟优化 + 持久化（约 2–3 周，两线并行）

**目标**：完整答复 p50 ≤ 15s；消除瞬态存储，全量数据可重启存活。

| 工作项 | 内容 | 验收标准 |
|---|---|---|
| 2-1 匹配层模型分级 | guideline 匹配（占调用 60–70%）切到 lite 档模型（qwen-turbo 级），生成/revision 留 deepseek-chat；经 LiteLLM 路由或自定义 NLP 服务 | 完整答复 p50 ≤15s；66 条回归通过率不降（≥92%）；单会话成本 ≤¥0.03 |
| 2-2 规则降频（备选） | 仅当 2-1 不达标时启用：按域分包匹配、低关键级降频；**高合规规则不降频**（FR-101 体系完整） | 同 2-1 口径 |
| 2-3 答复形态 | preamble + 长答复拆分推送（产品层免费收益） | 首响应维持 ≤4.5s，长答复分段到达 |
| 2-4 持久化切换（并行） | 会话/事件库切 MongoDB（dev03 容器已就位）；glossary/话术向量切 Qdrant（根治重启丢失） | 重启后全量数据存活（含术语）；种子脚本不再为补种而跑 |

**依赖**：迭代 1 完成（可靠性先行，避免把不稳定系统的延迟数据当基线）。**出口门槛**：2-1 与 2-4 验收达标。

## 迭代 3 · 渠道与验收（约 2–3 周）

**目标**：真实小程序流量可用；达到灰度评审全部硬门槛。

| 工作项 | 内容 | 验收标准 |
|---|---|---|
| 3-1 Java BFF | 会话/客户体系映射（openid→sessionId）、鉴权、渠道适配；**落地 1-2 的兜底话术层** | 小程序沙盒端到端走通；异常注入（杀引擎/拔模型）旅客均收到安全回复 |
| 3-2 转人工链路 | session manual 接管 + 坐席工作台对接 + 忙时溢出工单 | 转接后 AI 静默、坐席可见完整上下文；溢出场景生成回访工单 |
| 3-3 运营后台 v1（并行） | 规则中心（编辑器+冲突检测+沙盒试聊）、话术中心（版本治理）、会话 trace 回放 | 民航评审材料可导出：单条回复证据链（规则×知识×模板版本） |
| 3-4 520 全量压测（并行） | 补跑 chunk-2~4（分块执行器+健康检查已就绪） | 意图覆盖率 ≥85%、幻觉率 ≤2%、红线零违反、成本实测归档 |

**依赖**：迭代 2 完成。**灰度评审门槛（全部满足才可切流）**：

- 连续 100 轮零"已读不回"（1-1/1-2）
- 完整答复 p50 ≤15s（2-1）
- 重启数据全存活（2-4）
- 520 压测全指标（3-4）
- 审计证据链可导出（3-3）

## 统一口径与资产

- 延迟口径：首响应=preamble 到达；完整答复=ready/completed 事件（评测脚本已按此实现）
- 可靠性口径："已读不回"= customer 消息后无 ai_agent message 且出现 error 状态事件
- 评测资产：`evaluation/`（66 回归/520 压测）、`evaluation/cross/`（双线对照、多轮专项）
- 环境：本机（开发）、dev03 五容器（集成/后台开发）；BFF 部署位置随 Java 团队
