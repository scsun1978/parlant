## 1. 业务定位（为什么而设计）

管理后台不是"Parlant 的图形化"，而是客服运营团队的**工作系统**。业务只有三件事：

1. **让旅客答复持续正确**（质检闭环）：发现答得不好的 → 归因 → 修复 → 验证不再犯
2. **让政策口径安全地快变**（变更发布）：政策变了，今天内改口径，改得对、可审、可回滚
3. **让监管问不倒**（现场与审计）：任意回复，拿得出"为什么这样答"的完整依据

设计原则：

1. **工作流优先**：页面围绕"运营的一天"组织，对象 CRUD（规则/话术/知识）是工作流的下游工具，不是一级入口
2. **闭环可追踪**：每个 bad case 从发现、归因、修复到重放验证全程有链可查（民航审计"问题-修复-验证"留痕的天然材料）
3. **变更有护栏**：高合规变更走变更单 + 双人复核 + 异步回归门禁（保留 v2.1 决策）
4. **评测即运营**：66 回归/多轮专项是质量闸门（保留 v2.0 原则）
5. **与 Parlant 分层**：引擎归引擎，治理（权限/审批/版本/看板）归 Java BFF（当前 FastAPI 实现，生产置换）

## 2. 角色与权限（RBAC）

| 角色 | 业务职责 | 关键权限 |
|---|---|---|
| 客服运营 | 质检归因、修复起草、知识补录 | bad case 归因、编辑器起草（无发布权） |
| 话术审核员 | 审批修复物、放行变更 | 审批/发布、bad case 关闭确认 |
| 合规审计 | 抽查回复、导出证据 | 全量只读 + 审计导出 |
| 坐席班长 | 现场监控、接管、复盘分流 | 会话接管/代发、转人工会话标记入复盘 |
| 系统管理员 | 账号、渠道、模型分级配置 | 全部配置项 |

权限硬规则（沿用）：高合规变更双人复核；操作全留痕 append-only；权限校验在 BFF 网关层。

## 3. 信息架构（工作流视图）

```
管理后台
├── 质检工作台（默认页 · 一期主干）
│   ├── 队列：待复盘 → 待修复 → 待验证 → 已关闭
│   ├── bad case 详情（会话回放 + 四类归因）
│   └── 修复面板（按归因嵌入预填编辑器）
├── 会话中心（现场）
│   ├── 在线监控（转人工队列、已读不回告警）
│   └── trace 回放（延迟分解视图）
├── 变更发布
│   ├── 变更单（规则/话术/知识组合打包）
│   ├── 审批与灰度
│   └── 异步回归门禁 + 紧急通道
├── 编辑器群（被工作流调用，非一级入口）
│   ├── 规则编辑器（condition/action/关键级/组合模式/工具绑定）
│   ├── 话术编辑器（jinja2 + 槽位 + 渲染预览）
│   ├── 知识编辑器（文档/时效/召回测试台）
│   └── 术语表
├── 评测中心（回归集/变更门禁/报告归档）
└── 审计中心（证据链导出、append-only）
```

导航即工作流：**质检工作台 / 会话中心 / 变更发布 / 编辑器群 / 评测中心 / 审计中心**。

## 4. 核心工作流设计

### 4.1 质检闭环（一期主干）

**状态机**：

```
待复盘(pending_review) ──四选一归因──> 待修复(pending_fix)
待修复 ──挂接修复物──> 待验证(pending_verify)
待验证 ──沙盒重放通过 + 用例入回归集──> 已关闭(closed)
```

**发现入口（按 v3 评审排序）**：

1. **转人工会话复盘（主）**：班长接管的会话自动进入"待复盘"队列（天然"未解决"标注，零检测成本）
2. 人工抽检（辅）：按比例抽样常规化后开启
3. **已读不回（特例，一期即入）**：引擎 error 状态事件的会话直接进告警（不进归因流，进可靠性看板——迭代 1 专项指标）
4. 自动预警（红线/幻觉/负反馈）：二期接检测器

**归因与修复（四类归因 + 挂接）**：

| 归因 | 修复动作 | 挂接物 |
|---|---|---|
| 知识缺失 | 知识补录草稿（预填：旅客问题、AI 错误回答、会话链接、建议答案位） | 知识文档草稿 → B 发布流程 |
| 规则缺失 | 规则起草（condition 预填旅客问法、action 预填建议口径） | guideline 草稿（审批流） |
| 工具失败 | 工具工单（调用入参/错误/时间） | 工单 → 工具负责人 |
| 模型问题 | 记录 + 样本入对抗语料（含"模型输出不稳定"子类，承接 JSON 可靠性专项） | 语料条目 |

**关闭硬条件**：挂接修复物已生效 + 沙盒重放原会话通过 + 用例入回归集（evaluation 回归集自动沉淀）。

### 4.2 变更发布（二期，沿用 v2.1 决策）

- 变更单驱动：规则/话术/知识组合打包，沙盒验证（生产快照+草稿叠加，已实现）→ 双人复核 → 灰度 → **异步回归门禁**（提交即跑 66 回归，通过放行/打回附样例）→ 归档
- **紧急通道**：突发政策变更双人复核后先发布、2h 内补跑，未过告警建议回滚
- 编辑器起草即入变更单候选区，不再"单条直发"

### 4.3 现场与审计

- 会话中心（已建成）：实时监控、转人工队列（按原因分类）、已读不回告警、接管零成本（manual/auto + 代发）、trace 回放（preamble/各阶段/ready-completed 延迟分解）
- 审计中心：单条回复证据链（规则版本 × 知识 release 版本 × 模板版本）一键导出；append-only；留存 ≥3 年

## 5. 编辑器群（下游工具）

| 编辑器 | 要点 | 调用入口 |
|---|---|---|
| 规则编辑器 | 自然语言双栏 + 关键级/优先级/依赖 + 组合模式（高合规默认 composited_canned，strict 禁用）+ 条件式工具供给绑定（FR-404）+ 保存即冲突检测 + 试聊沙盒 | bad case"规则缺失"跳转（预填）/ 变更单 |
| 话术编辑器 | jinja2 + 槽位声明 + 渲染预览（定制组件）+ 版本 diff/回滚 + 槽位与工具 canned_response_fields 联动检查 | bad case 跳转 / 变更单 |
| 知识编辑器 | 文档管理 + 生效/失效时间 + **召回测试台**（RAG `/stages` 分阶段可视，已建成）+ `/reload` 热加载 + 知识缺口看板（检索为空 Top N） | bad case"知识缺失"跳转（预填）/ 缺口看板 |
| 术语表 | 术语 CRUD + 同义词；迭代 2 切 Qdrant 后转持久形态 | 直接入口 |

## 6. 评测中心

- **回归集管理**：66 种子/520 扩增/多轮 15 场景/双线对照；bad case 关闭用例自动入库
- **变更门禁**：高合规发布必过 66 回归（异步执行，发布单状态实时可见）
- **定期压测**：周/版本级 520 全量，报告归档对比（分类通过率、延迟双口径、成本）
- **可靠性看板**：已读不回率（目标 <2%）、JSON 纠错重试触发率（迭代 1 交付后接入）、工具成功率（≥98% 红线）

## 7. 技术方案（全定制，Appsmith 降级）

- **前端**：零构建静态页（vanilla JS，admin-bff 托管）——已验证形态，继续沿用；工作台为单页三栏（队列/详情/修复面板）
- **BFF**：FastAPI（当前实现，生产置换 Java BFF，接口契约不变）：bad case 状态机与挂接、审批流、审计、沙盒、SSE 事件订阅、评测执行器调用
- **数据**：治理数据（bad case/审批单/变更单/发布单/标注/评测报告）MongoDB 同集群不同库（ADR-0004）
- **实时性**：会话监控 BFF 事件订阅 → 前端 SSE；多副本经 Redis 转发（v2.1 决策保留）
- **部署**：dev03 容器（admin-bff:9000）；生产应用区 BFF×2
- **Appsmith**：降级为可选边缘工具（已建页面保留），不作主入口；后续是否退役视编辑器群覆盖度再定

## 8. 与 Parlant 的能力边界（沿用 v2.0 实测版）

| 能力 | Parlant 提供 | 后台自建 |
|---|---|---|
| 规则/话术/术语/Journey CRUD 与引擎执行 | ✅ REST API | 编辑器与工作流调用 |
| 规则冲突检测 | ✅ evaluation 服务 | 触发与展示 |
| 会话 trace | ✅ 事件流（status 阶段事件） | 回放、延迟分解、归因工具 |
| RAG 分阶段召回 | ✅（RAG 服务 `/stages` `/reload`） | 召回测试台、缺口看板 |
| RBAC/审批流/版本治理/发布/看板/评测调度 | ❌ | ✅ 全自建 |

## 9. 分期建设（对齐 A 线迭代计划）

| 期 | 范围 | 理由 |
|---|---|---|
| 一期（迭代 3） | **质检工作台**（转人工复盘入口 + 四类归因 + 挂接 + 重放验证 + 回归沉淀）、会话中心（已建成）、召回测试台（已建成）、审计中心 v1、基础权限 | 业务心跳先跑起来；民航评审硬门槛 |
| 二期 | 变更发布（变更单/审批/灰度/异步门禁）、评测中心、可靠性看板、知识缺口看板 | 运营闭环与规模化 |
| 三期 | AI 归因建议（用一期归因数据训练）、流程设计器画布化、抽检常规化、审计报表化 | 效率优化 |
