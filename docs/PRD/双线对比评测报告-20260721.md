# 双线对比评测报告：Parlant 线（A）vs 自研 hermes 线（B）

| 项 | 内容 |
|---|---|
| 版本 | v2.0（含评分口径纠偏、延迟实验、多轮专项与最终选型） |
| 日期 | 2026-07-21 |
| 评测对象 | A=`parlant` 仓库（Parlant 3.3.1 harness）；B=`pvg-agent-demo/implementation-v3`（自研 hermes runtime，robot API `hermes_runtime: enabled`） |
| 最终结论 | **分通道选型：文字客服走 A、数字人走 B、知识发布共用**（ADR-0001/0002/0003） |

> v1.0 的"B 单主线"结论经三轮证据纠偏后被推翻：① cross-a 的 PASS 口径存在系统性伪影（人工复核 8 例 PARTIAL，7 例 A 答案实质优良）；② "主航道"经定义纠偏为旅客服务全场景（A 的内容优势成为主航道优势）；③ 延迟实验与非线性多轮专项补齐了工程侧证据。本版为终版。

## 1. 评测方法与口径保真

| 方向 | 语料 | 评分口径 | 保真措施 |
|---|---|---|---|
| B → A（cross-a） | B 官方 621 例 | B 原版 PASS/PARTIAL/GAP 复刻 | 与 B 评分脚本差分测试：等价表逐字一致、judge_turn 九分支输出逐一相等 |
| A → B（cross-b） | A 自制 66 条 | A 原版 must_include/must_not_include/expected_tools | 修正三个测量偏差：reply 优先（B 部分 skill 口播错配）、B 知识活动经 references/skill 域识别、SSH 隧道保活重连 |
| 非线性多轮专项 | 自制 15 场景 36 轮（指代/反悔/插话/跳题/连续追问/边界/澄清/纠错） | 逐轮期望正则 + 全部文本人工复核 | A 侧完成判定用引擎 `ready/completed` 状态事件（静默窗口在 stream 模式下截断） |

**已知测量边界（终版口径）**：cross-a 的 B 版 rubric 奖励"B 自己的内部词汇"（skill/action 码）而非答案质量，其 PASS 数不能用于跨系统比较——B 的 74.1% 与 A 的 41.9% 不是能力差距。本报告跨系统结论一律基于人工复核与可复核的失败样例。

## 2. 总结果

### 2.1 单轮内容质量（人工复核为准）

- A 语料 66 条：A 98.5%，B 34.8%（adversarial 55.6% / long_tail 50% / normal 33.3% / multi_hop 0%）
- cross-a 人工复核（8 例随机 PARTIAL）：7/8 A 答案实质优良（安全口径、双段回答、结构化追问、时态感知"航班已起飞"），1/8 真实差距（日期槽位）
- **结论：单轮内容质量 A 明显优**，B 的政策类"安全但无用"（deflect/澄清/模板化）

### 2.2 非线性多轮（15 场景专项）

| | A | B |
|---|---|---|
| 场景通过 | **9/15（60%）** | 6/15（40%） |
| 轮级通过 | **29/36（80.6%）** | 22/36（61.1%） |
| 失败形态 | DeepSeek 结构化输出偶发非法 JSON → 引擎出错"已读不回"（7/36≈19%，可修） | 指代崩盘（"那婴儿票呢"→母婴室）、退改误解（"改签"→查航班）、政策类 deflect（8 轮"再确认"） |

### 2.3 延迟（实测）

| 指标 | A | B |
|---|---|---|
| 首响应（preamble） | 4.5s | —（无 preamble 机制） |
| 完整答复 p50 | 15–37s（流式无益；结构底线 8–15s） | **1.77s** |
| 阶段拆解 | 首次工具调用在 12–21s（前置 2–4 次 LLM 匹配/推断），每轮 5–7 次串行 LLM 调用 | 确定性管线，工具直出 |

### 2.4 工程与治理

| | A | B |
|---|---|---|
| 成熟度 | 3 天 PoC | 30 天 363 commits、1073 单测、812 回归 |
| 稳定性 | 压测期两次静默死亡（未定位） | 30 天连续 staging |
| 治理 | 无后台/审计 | 身份/审计/脱敏/工单/发布门禁全自研 |
| 数字人 | 零起点 + 延迟否决 | /robot/chat 已联调（621 例 GAP=0）；但口播模板错配 bug 必修 |
| 自评结论 | 多数达标、延迟未达标 | staging 就绪、生产 6–10 周收口 |

## 3. 内容质量差异的根因（范式分析）

> **A 用"LLM + 约束"换到泛化与内容质量，代价是延迟与工程风险；B 用"人肉规则 + 确定性"换到主航道单点的快与可控，代价是全场景的僵硬与"安全但无用"。**

- A：Guideline 自然语言规则（3 天 29 条）+ LLM 语义匹配（错字/口语/多意图泛化）+ revision 事实溯源（强迫具体口径）+ 通用模型的时态/上下文推理
- B：意图路由/skill/模板全为代码级资产（4064 行编排器、900 行合成器），主航道精雕细琢（槽位 98.59%、p95 2.6s），长尾无 skill 即误路由或 deflect；且小程序「航班动态」专门入口会分流简单航班查询，**客服通道的主体本就是长尾集合**
- B 的失败是**能力性的**（覆盖范式成本），A 的失败是**工程性的**（JSON 错误兜底、延迟结构），后者有明确修法

## 4. 最终选型（ADR-0001/0002/0003）

**分通道选型：**

1. **小程序文字客服：A 主线**。主航道能力（内容质量、多轮上下文）全胜；两个工程必修项：① DeepSeek JSON 错误重试+兜底话术（消除 19%"已读不回"）；② 延迟优化（首响应 4.5s 维持，完整答复经规则降频/匹配层模型分级压到 ≤15s）
2. **数字人语音客服：B 主线**。A 延迟否决；B 必修：口播模板错配 bug、政策 deflect 改引导（用 A 的口径资产，ADR-0002）
3. **知识发布共用**（pvg-v3-knowledge-release，B 为唯一发布方）；算力走云端路线（ADR-0003：现阶段互联网 API，生产专有云）
4. **B 的文本通道（/agent/chat 小程序面）不再投入**；B 聚焦数字人与治理资产复用
