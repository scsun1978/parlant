# 分通道选型：文字客服走 Parlant（A），数字人走自研 hermes（B）

经双向交叉验证与三轮纠偏（评分口径伪影修正、主航道重定义为全场景、延迟与多轮专项实测），决定**分通道选型**：小程序文字客服以 A 线（Parlant harness）为主线；数字人语音客服以 B 线（自研 hermes runtime）为主线；知识发布物（pvg-v3-knowledge-release）两线共用。本文取代"单一主线"讨论稿，为最终决策。

## Status

accepted（2026-07-21，grilling 会话确认）

## 证据链（docs/PRD/双线对比评测报告-20260721.md v2.0）

| 维度 | A | B |
|---|---|---|
| 单轮内容质量（人工复核） | 优：知识原文+具体口径、时态推理、安全且有用 | 弱：deflect/澄清/口播模板错配 |
| 非线性多轮（15 场景专项） | **60% 场景 / 80.6% 轮** | 40% 场景 / 61.1% 轮；指代崩盘、退改误解、政策 deflect |
| 延迟（实测） | preamble 4.5s，完整答复 15–37s，结构底线 8–15s | **p50 1.77s** |
| 回复可靠性 | DeepSeek 结构化输出偶发非法 JSON → 19% 轮"已读不回"（可修） | 失败也有回复（deflect） |
| 工程成熟度 | 3 天 PoC | staging 30 天、812 回归、自评 6–10 周收口 |
| 数字人 | 零起点 + 延迟否决 | /robot/chat 已联调（621 例 GAP=0） |

**核心逻辑**：A 赢的两项（内容质量、多轮上下文）是客服主航道能力且其缺陷（JSON 错误兜底、延迟优化）有明确修法；B 赢的三项（延迟、工程治理、数字人协议）是不可速建的工程资产——但 B 的内容短板恰可用 A 的资产修补（ADR-0002 方案甲）。因此文字通道取 A、语音通道取 B。

## Consequences

- A 线上线前两必修：① DeepSeek JSON 错误重试+兜底话术（消除"已读不回"）；② 延迟优化（规则降频/匹配层模型分级，目标完整答复 p50 ≤15s、首响应 ≤4.5s 维持）
- B 线上线数字人前两必修：口播模板错配 bug、政策类 deflect 改引导（用 A 的口径资产）
- A 线 PoC 验证报告补齐延迟实验与多轮专项证据后升版；PRD 第 8 章规划按 A 主线修订
- B 的文本通道（/agent/chat 小程序面）不再投入；B 聚焦数字人与治理资产复用
