# 内容审核服务自建（FR-704），不接既有/商用服务

渠道对接的内容安全（注入攻击/不当内容过滤，FR-704）采用自建审核服务：Java BFF 消息链路上的前置过滤（同步规则+注入检测）与质检侧后置抽检（LLM 评审）双层；不接入机场既有审核服务，不使用商用审核 API。

## Status

accepted（2026-07-26，迭代 3 评审确认）

## Considered Options

- 接入机场既有审核服务：复用现成能力，但接口协议/覆盖范围（针对内容发布而非对话场景）与责任边界不清，排期依赖外部门。
- 商用审核 API（阿里云绿网/腾讯 CMS 等）：开箱即用，但全量旅客对话出域（与民航数据治理和 PRD 私有化原则冲突），且客服场景特有的"政策口径类违规"（如诱导 AI 承诺赔偿）通用审核覆盖不到。

## Consequences

- 前置层（W2 交付）：注入检测（prompt injection/jailbreak 模式库）+ 不当内容词表 + 频控；命中即拦截并给出安全话术，留审计。
- 后置层（随质检闭环）：抽样 LLM 评审（幻觉/红线/不当表达），进 bad case 归因流（复用现有质检工作台）。
- 审核规则/词表作为话术资产走管理后台审批流治理（与兜底文案同口径）。
- W2 里程碑增加"审核服务上线"验收项：注入测试集（含角色注入/越权诱导/政策红线诱导）拦截率 ≥95%，误拦率 ≤1%。
